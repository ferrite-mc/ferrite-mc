# Ferrite 게임·월드 작업 병렬 계획

갱신: 2026-11-07. 이 문서는 작업 현황과 소유권을 기록한다. 기능 완료 여부는 소스, 테스트,
커밋, 실제 클라이언트 증거로 판단한다. Freebuff 지시문은 각각 Markdown 파일로 저장해 읽게 한다.

## 현재 진행 중인 파동

다섯 Freebuff 세션의 터미널 출력에서 작업 중인 것을 확인했다. 세션별 정확한 수용 결과와
커밋은 완료 보고를 받은 뒤 확인한다.

| 세션 | 현재 지시 파일 | 담당 범위 |
|---|---|---|
| `fb-end-respawn` | `freebuff-05-end-respawn.md` | 엔드 수정 배치 후 드래곤 재소환 시퀀스 |
| `fb-trader` | `freebuff-11-equine-inventory.md` | 말 인벤토리·장비 동작 |
| `fb-cross-region-leads` | `freebuff-08-leash-dimension-handoff.md` | 차원 경계를 포함한 리드/홀더 처리 |
| `fb-villager-trading` | `freebuff-12-villager-trade-transactions.md` | 여러 거래 화면의 권위 있는 거래 처리 |
| `fb-vault` | `freebuff-06-vault-client-sequence.md` | 볼트 클라이언트 이벤트와 상태 순서 |

Orca의 자동 입력 기록은 Freebuff가 거부한 프롬프트를 포함하므로, 실제 수동 입력 작업의
증거로 취급하지 않는다. 현재 진행 상태는 Freebuff 터미널의 작업 내용과 사용자가 확인한
세션 화면을 기준으로 기록했다. 끝난 세션은 새 세션을 만들지 않고 같은 세션에 다음 `.md`
작업을 배정한다.

## 이어서 병렬로 진행할 작업

세션이 끝나는 즉시 빈 슬롯부터 아래 독립 작업을 배정한다. 각 작업은 자체 `.md` 지시문,
파일 소유권, 회귀 기준을 갖게 하고 공유 통합은 코디네이터가 맡는다.

| 트랙 | 목표 | 경계와 완료 증거 |
|---|---|---|
| Bukkit/Paper 및 NMS | 미지원 Paper Server/Player 호출을 분류하고 실제 효과가 있는 API를 확장한다. NMS 의존 경로는 필요한 최소 클래스·필드·메서드부터 구현한다. | `java/ferrite-api-impl`, `crates/ferrite-plugin`, `crates/ferrite-server/src/plugins.rs`의 소유권을 작업별로 분리한다. `UnsupportedOperationException` 경로를 테스트로 추적하고, 실제 플러그인 결과를 지원 범위와 함께 보고한다. |
| 움직이는 피스톤 | 움직이는 블록 엔티티, 클라이언트 애니메이션·타이밍, 중단·재시작 동작을 완성한다. | `docs/pistons.md`의 남은 항목을 기준으로 `game/piston.rs` 및 피스톤 전용 영역 함수만 담당한다. 블록 상태·패킷·엔티티 동작과 실제 클라이언트 확인을 각각 검증한다. |
| 엔드 드래곤 | 단순 선회/다이빙을 바닐라 단계 행동으로 확장하고 돌진·숨결·화염구를 구현한다. 크레딧과 전투 저장/복원은 재소환 작업과 결과를 합쳐 검증한다. | 현재 재소환 세션과 파일 충돌을 피한다. 독립 드래곤 AI 자료형/행동 로직부터 진행하고, `end_fight.rs` 및 공유 영역 호출 통합은 재소환 작업이 정착된 뒤 코디네이터가 조정한다. 저장 기능은 현재 문서·코드에 NBT 저장 경로가 있으므로 재시작 시나리오로 실제 완결성을 판정한다. |
| 나머지 동물 | 고양이·앵무새 등 아직 빠진 상호작용, 번식·길들이기·행동을 조사해 구현한다. | 현재 말 인벤토리와 겹치지 않는 엔티티별 파일/테스트를 우선 소유한다. 실제 클라이언트에서 상호작용·메타데이터를 확인한다. |
| ASWM / Slime World Manager | Slime Region Format 월드 로드·저장·전환 및 플러그인 연동을 설계하고 구현한다. | 월드/Anvil 저장 계층과 멀티월드·플러그인 인터페이스의 소유권을 먼저 분리한다. 포맷 호환 fixture와 로드-저장 왕복 검증을 완료 기준으로 둔다. 참고: `optimization-references.md`. |

최적화 참고자료 조사와 테스트 환경·실행 순서 문서화는 코디네이터가 위 구현 트랙과 병렬로
진행한다. 실제 클라이언트 검증은 기능이 통합되는 대로 체크리스트를 실행하며, 실행하지 않은
항목을 통과로 표시하지 않는다.

## 마지막 단계

Rust 월드젠 구현은 **마지막**이다. 위 게임 동작·플러그인·ASWM 작업과 클라이언트 검증을
정리하고 나서 시작한다. 그때까지 사용자 JAR의 바닐라 월드젠 호스트를 유지하고, 바닐라
26.3 대조 fixture와 성능 기준을 보존한다.

## 병렬 작업 전체화와 통합 규칙

병렬 작업은 한 번에 최대 6개의 독립 워커로 나누고, 각 워커에 자체 Markdown 지시서와 파일
소유권을 준다. 각 지시서는 목표, 수정 허용 파일/함수, 제외 범위, 재현 가능한 수용 테스트,
실제 클라이언트 확인 여부, 커밋·캐시 정리 조건을 명시한다. 새 작업을 받을 때는 이전 작업
지시를 이어받지 않고 최신 배정 문서만 기준으로 삼는다.

- 같은 함수나 프로토콜 타입을 두 워커가 동시에 소유하지 않는다. `region.rs`, Java
  `Bootstrap.java`, 공용 packet codec처럼 통합 병목이 되는 파일은 기능별 삽입 지점만 맡기거나
  코디네이터가 최종 통합한다.
- 워커는 자기 브랜치에서 focused test, `cargo fmt --all -- --check`, scoped clippy 또는
  Gradle test를 실행하고 커밋한다. 코디네이터는 커밋·파일 범위·테스트 보고를 검토하고,
  통합 브랜치에서 충돌 해결 및 통합 검증 뒤 `main`에 반영한다.
- 증거 수준을 구분한다: 단위 테스트, 서버/JVM/프로토콜 봇 통합, 사용자 JAR differential
  검증, 실제 Minecraft 클라이언트 확인. 낮은 단계의 성공은 높은 단계 검증을 대신하지 않는다.
- ASWM/Slime 작업은 사용자가 별도로 시작하라고 할 때까지 배정하지 않는다. Rust 월드젠은
  게임·플러그인·클라이언트 검증이 정리된 다음 마지막 파동으로 둔다.

### 다음 병렬 파동 후보

현재 배정된 여섯 과제가 통합된 뒤, 미완료 여부를 소스에서 다시 확인하고 다음 여섯 슬롯을
사용한다. 각 행은 한 번의 집중 작업으로 끝나도록 자른다. 이미 구현됐다면 중복 구현 대신
수용 테스트와 상태 문서만 갱신한다.

| 슬롯 | 범위 | 경계와 완료 증거 |
|---|---|---|
| 엔드 전투 수명주기 | 수정 재소환·전투 상태의 재시작 왕복 중 남은 경로 | `end_fight.rs`와 전용 저장 테스트. 드래곤 공격 AI와 분리하고, 재시작 뒤 단계·수정·보스 상태가 한 번만 복구되는지 검증한다. |
| 피해·사망 이벤트 | Bukkit 이벤트 취소/변경 및 최종 드롭·XP 반영 | `plugins.rs`, Java `Bootstrap`, 전용 테스트. 손상 계산과 엔티티 AI 파일은 소유하지 않는다. |
| 구조물 변환 | 구조 회전 및 BlockTransformer 상태 보존 | Java structure API와 단위 테스트. facing/axis 외 상태를 좁게 선택하고 레일·계단 등은 golden case로 검증한다. |
| 플러그인 투사체 | 작은 화염구·눈덩이·달걀 중 미지원 경로 | 투사체 전용 helper/API 경로와 테스트. 엔더 진주 차원 이동과 공용 event bridge는 별도 작업으로 둔다. |
| 맵 표시 | MapView 장식 데이터와 플레이어별 패킷 동기화 | 맵 모델·전용 패킷 경로. 생성·갱신·제거와 늦게 접속한 뷰어를 검증한다. |
| 떠돌이 상인 | gamerule/biome/light/지면 기반 스폰과 음료 소멸 | trader spawn/AI 경로와 전용 테스트. 다른 동물 AI와 caravan 코드는 소유하지 않는다. |

각 후보를 시작할 때 이전 통합 이후 구현됐는지 다시 검색한다. 오래된 handoff의 TODO를
그대로 재구현하지 않고 실제 코드·테스트 기준으로 작업을 확정한다.

## 엔드 및 플러그인 현재 범위

- 사용자가 확인한 엔드 동작: 눈으로 엔드 포탈 활성화, 오버월드↔엔드 이동, 도착 플랫폼,
  사용자 JAR 월드젠 호스트를 통한 바닐라 지형, 공허 판정, 단순 선회/다이빙 드래곤, 보스바,
  엔드 수정 파괴·회복, 출구 포탈, 게이트웨이 이동.
- 남은 엔드 항목: 고급 드래곤 행동, 바닐라 수정 재소환 시퀀스, 크레딧, 전투 상태의 완전한
  저장·복원, 실제 클라이언트 검증. `docs/end-dimension.md`와 현재 `end_fight.rs`에는 NBT 저장
  경로가 기록되어 있으므로 저장 여부를 선언만으로 닫지 말고 전체 재시작 왕복을 검증한다.
- 사용자가 확인한 플러그인 상태: Paper Server/Player 일부 호출만 처리한다. 미지원 호출은
  `UnsupportedOperationException("Ferrite: not implemented: …")`로 드러나며, EssentialsX 등
  대형 플러그인 전체 경로와 NMS 의존 플러그인은 미지원 범위가 남아 있다.
